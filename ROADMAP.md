# Vantage desktop roadmap

Vantage should feel finished from the moment the VANTAGE wordmark appears at boot to the moment the laptop goes to sleep. The first milestone is a design and motion release with two always-on display (AOD) modes, one continuous wake and unlock sequence, deeper frosted glass, and responsive animation throughout the shell. Everyday laptop and app integration follows in the order people encounter it. Start with the VirtualBox guest named **Vantage (x86-64)**. Use the laptop for the things a VM cannot establish, then widen the hardware matrix.

The product is a complete Debian 13 amd64 desktop experience. Debian supplies the kernel, drivers, package system, login infrastructure, and system services. Vantage supplies the compositor, desktop and lock experience, Settings, visual integration, and eventually an optional preconfigured Debian image. The wordmark, Contours wallpaper, workspace controls, and bottom pill carry forward the Pi 4 visual identity. ColorOS supplies ideas about gesture-driven, interruptible motion and continuity from AOD to lock. Apple's material work supplies ideas about selective refraction, highlights, and translucency on controls. Vantage keeps its own artwork, layout, and interaction design. [Debian 13 release information](https://www.debian.org/releases/trixie/) · [OPPO's ColorOS 16 preview](https://www.oppo.com/in/newsroom/press/oppo-coloros16-first-look-revealed/) · [OPPO on continuous animation](https://www.oppo.com/en/newsroom/stories/oppo-find-x9-series-coloros-16-smooth/) · [Apple's Liquid Glass design session](https://developer.apple.com/videos/play/wwdc2025/219/)

## Delivery order

| Milestone | What someone can try | What makes it ready |
| --- | --- | --- |
| 1. Visual vertical slice | Boot, sign in, open Files and Console, move between windows and workspaces, lock, see either AOD, wake and unlock | The whole loop has coherent transitions, safe authentication, readable surfaces, responsive controls and VM recordings. |
| 2. Shell and appearance | Navigate the dock, launcher, overview, quick controls, notifications and Settings with the same motion and visual language | Real app identities and states, keyboard navigation, accessible fallback modes and usable composition on the laptop and VM. |
| 3. Daily laptop tools | Connect Wi-Fi and Bluetooth, control sound and brightness, use external displays, plug in a drive, close and reopen the lid | Physical hardware passes essential use and recovery tests. Apps behave correctly through sleep and display changes. |
| 4. App compatibility and distribution | Install or update with a Debian package, run common native, X11 and Flatpak apps, share a screen, and return to an earlier build | Clean installs and rollback work, key app scenarios pass, and multiple machines meet the support gates. |
| 5. Complete Debian edition | Boot from USB, explore the full desktop or install it with an installer, then manage the resulting system from the desktop | The image uses the same tested packages and includes a working update and recovery path. |

Packaging and test infrastructure can begin during milestone 1. Fullscreen, popup stacking, input delivery, and the lock boundary also move forward with the animations that depend on them. Work on larger items such as an installer, native app store, and remote desktop can proceed once their foundations are verified.

## Milestone 1 Visual identity and motion

### Design direction

- **Midnight as the signature theme.** Start with deep navy and near-black ink surfaces, a restrained cool blue rim, clean white primary text, and meaningful amber or red for important system states. Give the top bar and dock enough contrast and surface depth to anchor the wallpaper. Preserve the original VANTAGE stroke geometry.
- **Glass in layers.** Give dock, quick controls, overview menus, launcher, notification popovers and window chrome a visible blurred backdrop. Use localized highlights, specular edges and very slight refraction near rims. Keep file rows, text fields, terminal text, modal prompts, and other dense working surfaces more opaque. Use scrims that adapt to bright, black, and noisy content behind them.
- **Separate light theme.** After Midnight is coherent, build a deliberate brighter palette with near-white panes, cool gray layering, readable dark text, and its own shadows and tint. Check the same surfaces in both themes. Later offer schedule or system appearance, accent and wallpaper selection.
- **One set of visual rules.** Define platform font sizes and spacing, icon sizes, focus rings, shadow/elevation, surface tint, radii, inset edges, title bar controls, and motion timings. Use them in renderer-owned shell surfaces and themed GTK apps. Give active, hover, pressed, focus, selected, disabled, loading and error states visual distinction. Reuse Vantage's existing icon assets and a packaged symbolic icon family where it fits.
- **Readable alternatives from the beginning.** Offer reduced transparency with solid surfaces, high contrast, larger UI text, and reduced motion. Use 4.5:1 text contrast for normal text and 3:1 for large text and indispensable control indicators as design targets on actual composed surfaces. Verify the panel over a white browser, dark terminal, Contours, a high-frequency photograph, and a split bright/dark background. [WCAG 2.2 contrast criteria](https://www.w3.org/TR/WCAG22/)

### Shared motion rules

Extend the existing timeline with time-based transitions that can be interrupted and retargeted from their current pose. Share a monotonic clock and keep independent window and shell animations live together. Track the transition's source and target, so a dock-opened app can return toward its icon, a quick panel can contract toward the status cluster, and an overview card can return to its window. Springy motion fits icon and card transforms. Text, menus, lock prompts, brightness, and other controls use restrained easing. Use 90–140 ms for press and hover feedback, 160–240 ms for overlays, 200–320 ms for app/window choreography, and 220–340 ms as a first range for lock and wake. Tune these ranges after recording the interactions.

Make dragging, swipes and slider motion follow the pointer or fingers immediately. Commit or reverse at release based on distance and velocity. Update hit regions and clipping from the same transform as the renderer. Retarget when a window disappears or a monitor changes. Show useful pending or failure feedback for launches or slow application configure/acknowledge cycles. Treat asynchronous application buffers as arrivals within the animation. Handle slow, late, missing and superseded buffers without stalling input. Keep a stable focus owner throughout. Reduced Motion uses immediate placement or very short opacity changes and disables parallax, expansion overshoot, wallpaper zoom and movement of window thumbnails.

### Always-on display and lock experience

**Classic AOD.** A black or near-black scene with time, date and optional battery/charging indication. Use a choice of two readable clocks at first. The clock updates on its display precision, typically once a minute with seconds disabled. Keep content away from output edges, with subtle periodic repositioning useful on OLED and optional on other outputs. When the panel is really off, draw nothing and let normal wake restore the lock view.

**Wallpaper AOD.** A darkened full-screen version of the current wallpaper, an adaptive scrim, and a restrained accent. At wake, preserve the common clock and wallpaper coordinates, reveal the details of the lock view and bring in the password field on request. Precompute or cache the static wallpaper treatment. Idle wallpaper AOD uses damage-based updates. A short wake transition can use animated depth after the screen is active. Place a digital clock and small date over dim Contours, add a charging accent, and hold the clock in place as the credential prompt takes focus. Play one short charging animation when AC is connected.

**Settings and power.** Provide Off, Classic, and Wallpaper, with an on-AC option, timeout, optional clock style and 12/24-hour format. Propose AOD Off until opted in, with **on AC only** preselected on laptops when enabled. Support manual preview on the running desktop using design samples. On battery, default to normal display-off after the idle lock interval and allow explicit overrides. Docking, unplugging, low battery, media inhibitors, external sleep, lid close and resume all go through the same decision model. A black image still draws panel power on a typical LCD, so record measured laptop cost before offering longer defaults. Honor display-off and actual sleep. HDMI/DisplayPort screens can default off while the internal display shows AOD.

**Security boundary.** Model desktop, lock requested, safe opaque frame, lock UI, AOD, display-off and suspended as related states with clear allowed transitions. Compositor-owned visuals can draw wallpaper and sanitized clock/battery data. The compositor takes password input while normal Wayland surfaces are unfocused. A separate helper verifies it with Debian PAM over a private pipe. Preload trusted lock/AOD assets. Use trusted wallpaper and graphics as the lock transition's only visual sources. The compositor must stop capture delivery before lock content appears and leave every screen covered while a locker starts, crashes, or an output attaches. Lock acknowledgement waits for the secure frame on every participating output or a safely disabled output. Ending lock requires authenticated unlock or deliberate recovery through an authorized greeter/logout path. Suppress private titles, wallpaper previews from arbitrary apps, notifications, camera thumbnails, media metadata and user files from AOD by default.

**Wake interaction.** Accept a deliberate keyboard or pointer wake and a configurable touchpad wake policy. Quiet small pointer movements can be ignored while dimmed to avoid waking from noise. Decide which events only reveal the prompt and which belong to input after focus exists. Cover first password keystroke, wrong password, retry, caps lock, keyboard layout, screen off, hotplug and lid transitions. Add a clear accessible indication for users who cannot see the current mode. Preview mode offers a way out when the test user has a locked Debian password, and actual lock uses valid PAM authentication and documented account setup.

**AOD acceptance.** Both styles run for 30 minutes in the VM with no continuous repaint when settled, wake from keyboard and mouse, load after reboot, and survive ten lock/unlock cycles. On the laptop, record measured idle, AOD and display-off power on AC and battery, including whether the display's actual mode or brightness changes. Test suspend triggered by the menu, by logind and by lid close. Record blur-on and blur-off motion separately. Add a test window with a conspicuous private pattern and assert it is absent from AOD, outputs attached after lock, and capture streams once lock begins. Wrong password, killed locker, missing locker, resume without cursor, and two displays each need a recovery test. [Debian 13 logind API](https://manpages.debian.org/trixie/systemd/org.freedesktop.login1.5.en.html)

### Rendering and responsiveness

- Measure frame build time, submit time and missed frames for the appearance slice first. Record median and P95/P99 timings and expose selected backend, modes, FPS and effect costs in diagnostics. Use monotonic time and DRM presentation where available.
- Scope damage for moving windows, popovers and cursor, including the areas a blur kernel depends on. Cache static wallpaper, mask, shadow and typography textures per scale. Reuse shared or region-based blur work when the backdrop and quality match. Keep GPU objects owned by the compositor/render path.
- Offer Full, Balanced and Reduced effect presets. Full uses richer multi-pass frost and highlights. Balanced uses downsampled blur and fewer high-cost regions. Reduced uses strong tints, static depth and simplified shadows with motion retained where affordable. Set a reasonable starting preset from measured behavior or renderer capability, keep manual selection, and avoid changing quality visibly mid-transition. Accessibility modes override visual effects.
- Run D-Bus calls, thumbnail decoding, image processing and package/app indexing off the compositor's critical path. Bound queues, coalesce repetitive events, and discard stale work when UI closes. Keep ordering for focus, surface commits, modesets and authentication. Evaluate a separate render thread only if profiling justifies it and tests cover context ownership, fencing and shutdown. Measure compositor parallelism using a profile of concurrent work and frame timings. LLVMpipe already uses CPU threading within its renderer. [Mesa LLVMpipe documentation](https://docs.mesa3d.org/drivers/llvmpipe.html)
- For initial tuning, frame budget is 16.7 ms at 60 Hz and 8.3 ms at 120 Hz, including backend work. Establish baselines on the actual VM and laptop. A proposed gate is P95 frame preparation within 70% of the refresh budget on the supported default preset during repeated window/overview transitions and <1% missed presentation intervals in the agreed sequence. Record P99, capture overhead and dropped frames even where softer targets are used. During settled AOD and idle desktop, check for event-driven updates and verify that 30-minute idle memory does not climb. Publish hardware-specific results.

### First implementation batches

2. Add shared colors, typography, edges and timing. Land revised Midnight dock, top bar and Quick Settings together with a Reduced Effects control and screenshot pairs. Add visual regression fixtures with deterministic wallpaper and clock.

Exercise rapid reversal and concurrent animations. Fix missing fullscreen and popup handling while touching these paths.

5. Finish coordinated Plymouth, greeter theme and shell first-frame art in a clean guest. Use common assets and matching backdrop framing. Keep safe greeter fallback, boot messages and any OS/disk-password flow functional. Publish a complete boot-to-unlock recording and separate Classic and Wallpaper AOD recordings.
6. Deploy the visual slice to the known test VM, capture comparisons on bright and dark backdrops and software rendering, then arrange native testing of the laptop with the package and recovery session. Gate the following milestone on safe lock, controllable performance and usable keyboard input.


## Milestone 2 Complete shell and appearance

### Windows, workspaces and touchpad

1. **Window protocol correctness.** Handle xdg fullscreen and unfullscreen, window menu, popup grabs and input serial validation, nested popup placement with work-area constraints, transient stacking, dialog focus, parent-window teardown, resize cancellation and compositor- versus client-side decoration negotiation. Start tests in Firefox, Thunar and GTK Settings, then add a Qt app and an X11 app. Fullscreen restores the previous maximized, tiled or floating state and hides shell surfaces on the correct output. A menu can close on click-away or Escape without swallowing the next click.
2. **Activation and app identity.** Resolve Wayland app IDs, X11 WM_CLASS and installed desktop IDs, with a controlled fallback for missing metadata. Support xdg-activation and appropriate startup feedback. Keyboard focus follows explicit action, such as a valid launch or switching window. Background requests may mark an app as needing attention. Test launched versus already running apps, child dialogs, text input while an app starts, open-file links and an app whose first window appears on another workspace.
3. **Dock behavior.** Support active and inactive indicators, attention, minimized and running states, multiple windows per app, pin/unpin, drag reorder, context menus, open new, close, and placement on primary or all displays. Persist pinned desktop IDs and order. Show removable device or Downloads shortcuts only if enabled. Keep direct keyboard action for every gesture. Context menus and badges share the same glass and input behavior as other panels.
4. **Workspaces and overview.** Keep the familiar three workspaces as the default, add names and optional count, and give each a last-focused window. Add Super plus number to switch, Super+Shift plus number to move, and a move menu and overview drag. Use stable labels and meaningful empty states. Overview provides view-all and per-workspace navigation, robust timing on thumbnail close, keyboard shortcuts and move across displays. Live snapshots have a bounded memory/lifetime policy.
5. **Touchpad and touchscreen.** Add configurable three-finger workspace swipes, an overview gesture chosen after conflict testing, and hold/drag interactions. Libinput supplies calibrated device events. Decide which app input stays available during shell gestures, and keep standard scrolling, pinch-to-zoom and tap-to-click usable. Test slow, fast, reversed and diagonal gestures, adding a finger mid-swipe, hotplug and target removal. Touchscreen taps should work on lock, shell and apps where supported. [libinput documentation](https://wayland.freedesktop.org/libinput/doc/latest/)
6. **Window rules and layout.** After base behavior is stable, introduce per-app placement and workspace rules, split ratios, quarter snapping and move to display. Preserve visible work on output removal. Treat session reopen as opt-in and limited to apps that can reopen safely. Support staged placement for eligible apps.

### Launcher, status, notifications and calendar

- **Launcher and running apps.** Use desktop files and actions with categories, keyword matching, icon and label lookup, history controls, proper URI launch, and keyboard selection. Add optional search providers later for Settings, open windows and local files. Separate recent usage from indexed personal file search and allow both to be turned off. Support Latin and non-Latin locale text through the same Unicode/full-size layout path before committing a translation set. [XDG Desktop Entry Specification](https://specifications.freedesktop.org/desktop-entry/latest/)
- **Quick Settings.** Build fast tiles for network, Bluetooth and audio, brightness and volume sliders, battery state, Do Not Disturb, a small media row, and a precise power submenu. Distinguish connected, connecting, off, unavailable, permission required, and error. Pinning or rearranging quick controls can follow. The clock leads to calendar and alerts. Match the icon tooltips and labels to larger Settings pages so a user can go straight to the relevant control.
- **Notifications.** Implement the D-Bus notification interface with action, replace, close and expiration behavior. Stack banners, group by app, limit bursts, add history, DND, per-app controls and separate safe lock behavior. Keep a capped in-memory history initially, with persistence opt-in and a clear history action. Marshal labels and images safely, avoid leaking payloads in logs, and offer private default behavior across sessions and shared screens. Test browser, terminal and network service notices before wiring notifications for every adapter. [Desktop Notifications Specification](https://specifications.freedesktop.org/notification/latest/)
- **Status tray and calendar.** Implement a supported StatusNotifier host, overflow menu, app menu handling, icon changes and vanished app cleanup. Include calendar grid, date formatting, week-start option and navigation by keyboard. Calendar account and sync integration can arrive through an optional supported provider while keeping a local month view available. Add media controls based on MPRIS for active players with correct behavior when the player vanishes. [StatusNotifier Item Specification](https://specifications.freedesktop.org/status-notifier-item/latest/)
- **Desktop comfort.** Revisit icon tooltips, preferred output for notifications, optional auto-hide, focus mode and quiet hours, wallpaper crops and fit, battery warnings, and onboarding after every control has a maintained source of truth. Add distinct hovers and actionable states instead of decorative status text.

| UPower and logind | Battery, charging, estimated time, lid and idle policies, supported power profiles, real laptop brightness. | AC/battery transition, no batteries, critical state, suspend from outside Vantage, audio/brightness buttons and docked lid behavior. [UPower reference](https://upower.freedesktop.org/docs/) · [Debian logind API](https://manpages.debian.org/trixie/systemd/org.freedesktop.login1.5.en.html) |
| UDisks2/GVfs | Mount, unlock, show in Files and eject with feedback. | Disk busy, failed unlock, canceled authentication, read-only USB media and unplug during transfers. [UDisks2 API](https://storaged.org/doc/udisks2-api/latest/) |

Debounce rapid control writes and use service events as the source of truth for both quick controls and settings. Give user-invoked commands deadlines, cancellation, clear error states, and supported advanced dialogs. Start with existing helpers where they work and replace a helper when the native path reaches parity. Remove raw status polling for each domain after its replacement behaves through a daemon restart. Use a working polkit agent whose prompt can be tested on Wayland. Support permission denial and cancellation for Wi-Fi, devices and system settings. Use existing authority boundaries for passwords, secrets and privileged actions.

### Power and login life cycle

- Subscribe to the local logind session's lock and sleep events. Set the session's locked hint after the secure scanout barrier. Arm the delay inhibitor early and release it on a secure frame or policy-defined safe timeout. Reestablish it after resume. Check seat changes, crash behavior and the wake key path. Login greeter and authenticated lock are distinct surfaces with their own recovery. [Debian logind API](https://manpages.debian.org/trixie/systemd/org.freedesktop.login1.5.en.html)
- Inspect idle inhibition for fullscreen video and presentation, plus lock-on-idle, lock-before-sleep and display-off timing. The explicit lock action always works when an app inhibits idle. Provide a media/presentation indication and a controlled way to override idle power behavior.
- Use one policy for suspend, lid close, power button, docked operation and external suspend. Respect logind inhibitors and polkit for restart and shutdown. Add confirm dialogs with the effect of each action, including open apps and pending updates when those signals are available. Offer hibernate after actual configuration and recovery tests.
- Integrate backlight via a supported privileged interface, such as logind SetBrightness when applicable. Detect the relevant internal panel and map controls appropriately, preserving the last safe brightness. Software dim can remain an explicitly labeled display effect for VMs and external outputs. DDC/CI is optional once device diversity and permissions are understood.
- Put Vantage session-lifetime helpers under a scoped user service target after the Wayland socket is ready. Use clear dependencies, ownership, timeouts, cleanup, log scopes and bounded restart. Handle logout from a busy app, cookie cleanup, systemd/D-Bus display environment, other desktop sessions under the same user, expired prompts and user switching. Fatal compositor errors land at a usable greeter or documented recovery path. [Debian systemd user-session targets](https://manpages.debian.org/trixie/systemd/systemd.special.7.en.html) · [XDG Autostart](https://specifications.freedesktop.org/autostart/latest/)

### Displays, graphics and input

1. **Model outputs independently.** Track connector, mode, position, scale, transform, enabled state, work area, scene damage and pending frame. Use stable hardware identities with graceful ambiguity for duplicate displays. Separate KMS discovery and configuration from shell geometry and from wl_output publication. Make seat pause/resume, loss of GPU access and failed submission recoverable when possible.
2. **Hotplug and mode changes.** Subscribe to udev/DRM changes and reconcile configured outputs. Start with hotplug on one GPU and managed device restarts. Introduce per-CRTC scheduling, safe atomic test and commit where available, and a last known good rollback. Confirm risky changes with a countdown, recover on timeout or unplug, and resolve output removal before setting new focus or enabling apps.
3. **Multiple outputs and DPI.** Ship extended and mirrored arrangements, drag to place, primary selection, 1×/2× then fractional scale, high refresh, rotation and saved dock layouts. Validate cursor and popups crossing unlike scale, maximization on each display, apps moving after unplug, fullscreen on the correct output and lock surfaces during hotplug. For fractional scale, use coordinated buffer scaling, viewport and surface geometry and verify all three of GTK, Qt and XWayland.
4. **Input completeness.** XKB layout switching, repeat, compose, multimedia and power keys, focus without mouse, pointer acceleration settings, touchpad tapping and natural scroll, high-resolution wheel data, touch and later tablet tools. Keep layout choices available on the lock screen. Test actual laptop keyboard, external keyboard, touchpad and mouse, device unplug mid-drag, wrong gesture reversal, and lid wake into a secure focus state. Add configurable per-device actions before supporting many exotic devices.
5. **GPU support matrix.** Laptop and VirtualBox first. Expand to Intel and AMD configurations supported by Debian's kernel and Mesa, then NVIDIA and hybrid cases through measured DRM/KMS, DMA-BUF and synchronization compatibility. V3D is Broadcom's renderer on hardware such as Pi 4. For amd64, measure the installed GPU driver and renderer and report VirtualBox with acceleration on and off separately if both can be tested. Start with one render device plus multiple connectors. Only then tackle cross-GPU buffer import, laptop dGPU-only ports and hot-unplug recovery. [Linux DRM/KMS documentation](https://docs.kernel.org/gpu/drm-kms.html) · [Smithay 0.7 native DRM example](https://github.com/Smithay/smithay/blob/v0.7.0/anvil/src/udev.rs) · [Mesa V3D documentation](https://docs.mesa3d.org/drivers/v3d.html)

**Milestone 3 gate.** On physical Debian 13 hardware, run repeated lock, lid and suspend cycles using real credentials. Connect a display at two modes, roll back one mode on timeout, unplug while a window is fullscreen, then repeat while locked. Join Wi-Fi from Settings, confirm a Bluetooth device and real audio where adapters are available, plug in USB while copying, eject, and sign out and back in. A login helper failing or a service restarting should leave the desktop and recovery available.

### Portals, screenshots and screen sharing

1. **Basic portals.** Package desktop-specific backend selection using supported implementations for FileChooser and other basic portals. Use the expected XDG desktop environment and correct activation environment. 2. **Screenshot and recorder.** Offer an interactive Print key overlay for region, window and output capture, copy/save, and an optional delay. Provide minimal permission UI for apps invoking capture. Use an opaque indicator in fullscreen as needed. 3. **ScreenCast.** Choose capture protocol and backend after checking Debian package compatibility, or implement Vantage's portal backend and PipeWire producer. Pick monitor, then window and region as supported. Add approval, cancel, unambiguous active-sharing indication and stop command. Handle capture buffers and timestamps with bounded flow and no blocking of interactive rendering. [XDG Desktop Portal backend guide](https://flatpak.github.io/xdg-desktop-portal/docs/writing-a-new-backend.html) · [ScreenCast API](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html)
4. **Permissions and follow-up.** Centralize local UI for recording and permission indicators. Request only permissions required per operation. Bind consent to request, app identity and selected source. Revocation independently stops access, including when tray or overlay restarts. Add screencast preferences, permission listing and GlobalShortcuts only after their ownership semantics are defined. Remote Desktop is a later isolated feature with its own consent, input control and lock tests.

### Packaging and maintenance

- **Initial package.** Build an amd64 Debian package on a clean Debian 13 base, with Vantage compositor, Console, desktop entries, artwork, configuration and docs. Derive runtime dependencies and separate optional recommendations for tools, XWayland, portal and integrations. Use package-managed system paths and versioned artifacts. Include debug symbols for support, license and asset attribution, and a build manifest. Install package and select Vantage at login with existing session choices visible. [Debian Policy on files](https://www.debian.org/doc/debian-policy/ch-files.html)
- **Migration and upgrades.** Detect the old local test deployment and document a clean transition. In particular, account for '/usr/local/bin' precedence and the old session descriptor. Preserve user settings, allow restore of the previous package and state, and ensure normal remove/purge and reinstall. Keep versioned preferences, last known display config, and safe defaults. Use idempotent scripts with appropriate failure behavior. [Debian maintainer script policy](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html)
- **Boot assets.** Package Plymouth separately or as an optional integration with explicit activation and a restore path. Keep the user's prior loader and display manager choices. Test plain boot, verbose boot, recovery entries, restart, firmware/boot mode variations and a working disk-encryption prompt on an owned test image. Splash-to-greeter can align palette and asset placement even when an early mode change briefly blanks the screen.
- **First deployment.** Refresh the named VM with the package and scope system integration changes to that test environment. Verify the install on a separate clean VM and on a machine already using another Debian desktop. Use a verified artifact transfer and a known-good snapshot or package. Record what was installed and which logs, screenshots, package versions, and kernel apply.
- **Updates.** Start with signed or checksum-verified artifacts through an authorized release channel. Later, maintain a signed APT repository with key rotation and a rollback window. Use APT and Debian's update mechanisms for system dependencies. Consider a desktop update panel hooked into established privileged package services after CLI installation is reliable. Preserve choice over installing, timing and reboot. [Debian APT signature verification](https://manpages.debian.org/trixie/apt/apt-secure.8.en.html)
- **Recovery.** Add a Safe Graphics session entry with reduced effects, a safe mode and a separate known-good settings path. Document greeter and TTY recovery. Show a direct way to retry a display change or restore the previous session after a known bad configuration. Keep app and personal data through uninstall, downgrade and change of session.
- **Diagnostics and support.** Log version, modes, renderer, seat, pageflip and session lifecycle with useful reasons. Make a user-reviewed diagnostics bundle and standard bug report template. Keep file paths containing usernames, hardware IDs, networks, credential material and notification or capture data out of routine reports. Ask for targeted fresh measurements when needed.
- **Build and release gates.** Debian job runs Rust formatting, strict Clippy, tests, release builds, shell checks, desktop-file validation and package linting. Package and install from clean images, including offline dependency/failure handling where supported. Add bounded nested-session CI smoke tests and native/manual configuration matrix. Keep prior green artifacts available for rollback. Release packages only after review and authorization under the repository rules.

**Milestone 4 gate.** Install under a clean Debian 13 VM without a Rust toolchain. Exercise login, logout, upgrade, reinstall, remove and rollback while another desktop remains selectable. In that build run the browser meeting and one screen share, cancel a Flatpak file chooser, test one GTK, Qt, Electron and X11 app, and verify sent and received text/file drag operations. Repeat must-pass desktop workflows on the laptop and one alternate graphics stack before claiming broad x86-64 support. Publish a tested support matrix for optional features.

## Milestone 5 A complete Debian edition

1. **Install or try live.** Once package management survives upgrades and rollback, produce an optional Debian Live build using those same signed packages and an established Debian installer path. Use clear language about storage and private data. Test USB live sessions, EFI boot on VM and available hardware, install alongside and full disk only in dedicated test disks, disk encryption, offline/network install, language, time zone and user setup. Offer a fallback session and reachable recovery. [Debian Live project](https://www.debian.org/devel/debian-live/)
2. **Welcome and first-run experience.** Display physical/hardware readiness, language and keyboard, themes/effects, animation preference, desktop tour, power and AOD, user-level updates and favorite apps. Respect migrated settings. Allow skip and resume pages. Follow install with everyday task prompts from the launcher or Settings where people can find them again.
3. **System and software center.** Use Debian package operations with normal authorization, plus optional Flatpak catalog if wanted. Start with available updates, changelog, installation, removal, progress, cancellation when possible, and understandable recovery after failure. Offer reboot later. Build software search, screenshots and optional sources after handling accurate identity, provenance, permissions, licensing and offline behavior.
4. **Complete workflows.** Provide tested browser/document/PDF, archive, audio/video, camera, file sync choices, printer/scanner, password/keyring, backup/restore and default app management without preselecting account or online service providers. Print, scan, backup and restore through existing tools initially. Integrate appearance, status and navigation around tested tools.
5. **Maintenance over time.** Document the Debian 13 lifecycle boundary and the independent Vantage update cadence. Offer release notes, supported device matrix and recovery image guidance. Test repeated upgrades from supported prior packages. Verify that critical fixes can be shipped without changing the full image. Consider additional language packs and community documentation after core workflows pass.

**Milestone 5 gate.** Someone can boot the live image, install on an empty test disk, create their account, choose a language, update, set a theme and AOD, install/open common apps, handle USB and networking, lock, sleep and resume, and recover from a failed update or mode change using the documented path. Evidence includes an encrypted install, a physical laptop, a second hardware configuration and clean rollback testing.
